REMEDIATED FINDINGS
================================================================================
1.  Hard-coded credentials in tracked files                         RESOLVED
    - .env.example contains placeholders only.
    - .env and .env.* are ignored by Git.
    - Initial President credentials are read only from ignored local/deployment
      configuration and are never returned by the API.

2.  Missing CSRF protection                                         RESOLVED
    - Stateful requests require a session-bound HMAC CSRF token in the
      X-CSRF-Token header.
    - The browser API client automatically fetches and refreshes this token.

3.  Weak password requirements                                      RESOLVED
    - Login, member creation, and password reset require 12-128 characters
      with uppercase, lowercase, numeric, and symbol characters.

4.  No account lockout                                              RESOLVED
    - Failed attempts are recorded per user.
    - Accounts lock after the configured threshold (default: 5) for the
      configured duration (default: 15 minutes).

5.  Inadequate session cookie protection                            RESOLVED
    - Cookies are HTTP-only, SameSite=Strict, rolling, and Secure in
      production. HTTPS is mandatory in production.

6.  Plaintext database session data                                 RESOLVED
    - Session payloads use AES-256-GCM encryption before storage in MySQL.
    - Encryption keys are validated 32-byte keys from environment secrets.

7.  No password-recovery workflow                                   RESOLVED
    - Forgot/reset endpoints use cryptographically random, SHA-256-hashed,
      single-use tokens that expire after 15 minutes.
    - Production requires verified SMTP configuration at startup.
    - Reset completion invalidates other sessions.

8.  Missing multi-factor authentication                             RESOLVED
    - TOTP enrollment, verification, disable, and login-challenge routes exist.
    - TOTP secrets are encrypted at rest; setup returns a QR enrollment image.

9.  No admin-write rate limit                                       RESOLVED
    - President write operations are limited to 30 per minute per user/IP.

10. No global/per-user API throttling                               RESOLVED
    - Global, authentication, authenticated-user, MFA, password-reset, and
      admin-write limiters are active.

11. No audit-log retention                                          RESOLVED
    - Retention job runs daily; default retention is 365 days and configurable.

12. Unvalidated user identifiers                                    RESOLVED
    - Administrative target IDs must be Prisma CUIDs; invalid identifiers
      receive a generic 404 and produce an audit event.

13. Missing CSP                                                     RESOLVED
    - Helmet applies a restrictive CSP, blocks objects and frames, and limits
      scripts, images, forms, and connections to explicit origins.

14. Missing security headers                                        RESOLVED
    - Helmet defaults, HSTS in production, Referrer-Policy,
      X-Permitted-Cross-Domain-Policies, and Permissions-Policy are enabled.

15. Permissive/implicit production CORS                             RESOLVED
    - Production requires an explicit CORS_ORIGIN allowlist.

16. Generic errors without support correlation                      RESOLVED
    - Errors are server-logged with a request ID; clients receive a generic
      error plus a safe error ID.

17. No logout-all-devices                                           RESOLVED
    - Session issue time is checked against a per-user invalidation timestamp.

18. Invalid permissions / role escalation                           RESOLVED
    - Permission values are enum-validated, duplicate assignments are blocked,
      and account creation always creates a STUDENT role.

19. Missing API contract                                            RESOLVED
    - Versioned OpenAPI 3.0 JSON is available at /api/v1/docs.

20. Production source maps                                          RESOLVED
    - Production build emits no source maps.

21. No API versioning                                               RESOLVED
    - Browser and server routes use /api/v1.

22. Incomplete audit change details                                 RESOLVED
    - Account-status and permission changes log before/after metadata.

23. Session fixation exposure                                       RESOLVED
    - Session IDs regenerate at password authentication and MFA completion.

24. Unsafe frontend data rendering                                  RESOLVED
    - React's escaped rendering is used; there is no dangerouslySetInnerHTML
      or HTML injection API in the client source.

25. Dependency vulnerability scanning                               RESOLVED
    - npm run audit:dependencies is provided; current audit is clean.

26. Database startup validation                                     RESOLVED
    - The server verifies the database before listening; health exposes only
      connected/unavailable status.

27. Sensitive User-Agent retention                                  RESOLVED
    - User-Agent values are SHA-256 hashed before audit storage.

28. Fixed bcrypt work factor                                        RESOLVED
    - BCRYPT_ROUNDS is validated environment configuration (12-16).

29. Uncontrolled process shutdown                                   RESOLVED
    - Shutdown drains HTTP connections for up to 30 seconds, then closes the
      session store and Prisma connection.

================================================================================
OPEN FINDINGS / REQUIRED PRODUCTION OPERATIONS
================================================================================
M1. Distributed rate-limit persistence                              MEDIUM
    Current state: Express rate-limit uses in-memory counters.
    Risk: Limits reset on restart and are not shared between multiple API nodes.
    Required before multi-instance deployment: use Redis (or equivalent) as the
    rate-limit store.

M2. Central monitoring and alerting                                 MEDIUM
    Current state: Security events are audit-logged and runtime errors are
    written to application logs with request IDs.
    Risk: No SIEM/Sentry/alert destination is configured.
    Required: connect logs and alerts to the chosen operational monitoring
    service; alert on lockouts, MFA failures, 5xx rates, and admin changes.

M3. Email verification                                               MEDIUM
    Current state: Profile email syntax is validated, but ownership is not
    verified before it can receive a password-reset email.
    Required: add an email-verification token and require verification before
    enabling recovery delivery for member accounts.

M4. Backup and disaster-recovery procedure                          MEDIUM
    Current state: Local MariaDB data is persistent, but no automated backup,
    off-device retention, restore test, RPO, or RTO is configured.
    Required before public launch: daily encrypted backups, off-device copies,
    monthly restore test, and documented recovery objectives.

M5. MFA account-settings user interface                             RESOLVED
    - The authenticated Account Security page supports TOTP QR enrollment,
      verification, status display, and disabling MFA with password and code
      confirmation.
    - Every control surfaced on the live President dashboard now leads to a
      protected, API-backed action; unavailable product modules are not shown
      as inert dashboard buttons.

M6. Audit export / immutable archive                                MEDIUM
    Current state: Audit records are retained then purged locally.
    Risk: The local database is not an immutable archive.
    Required for regulated retention: export signed/immutable audit records to
    controlled external storage before local retention deletion.

L1. CSP permits inline styles                                       LOW
    Current state: style-src includes 'unsafe-inline' for the current React/Vite
    styling approach. Script execution remains restricted to self.
    Improvement: migrate inline style attributes to hashed/nonced styles where
    practical.

L2. CI enforcement is not configured                                LOW
    Current state: build, lint, test, and dependency-audit commands exist.
    Improvement: run them as required checks in the source-control CI pipeline,
    along with secret scanning and dependency-update alerts.

L3. Static portal content                                           RESOLVED
    - The live dashboard exposes only operational controls backed by the local
      API: member management, audit-log review, account security/MFA, and
      sign-out.
    - Events, registrations, payments, QR, notifications, and gallery modules
      remain future product scope and are not presented as live controls.
